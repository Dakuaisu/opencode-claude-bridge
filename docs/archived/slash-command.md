# Archived: the `/claude-pool` slash command

Removed in favour of the interactive TUI (`claude-pool dashboard`). Kept here
because it becomes worth revisiting the moment opencode can render a dialog.

## Why it was removed

Two hard limits in opencode, both verified against the shipped binary rather
than inferred:

1. **A command always costs a model turn.** The command path is:

   ```js
   yield* d.trigger("command.execute.before", {...}, { parts: xe });
   let W = yield* fe({ sessionID, messageID, model: K, agent: te, parts: xe });
   ```

   `fe()` (the prompt call) runs unconditionally. A plugin cannot cancel it.
   Emptying `output.parts` in the hook does not suppress the turn — it just
   sends an empty message, which made the model improvise. `TextPartInput`
   accepts `ignored: true`, but that does NOT stop the part reaching the model.
   The prompt API has a `noReply` flag that would solve this, but it is not
   exposed to plugins.

2. **A plugin cannot open a popup.** `tui.publish` accepts exactly three event
   types:

   ```ts
   body?: EventTuiPromptAppend | EventTuiCommandExecute | EventTuiToastShow
   ```

   There is no dialog event, and `/rename`-style pickers are compiled into the
   TUI. Only a change to opencode itself can expose one.

## What to do if opencode adds a dialog event

Restore the hook below and point it at the new event instead of a toast. The
dashboard renderer (`src/pool/dashboard.ts`) and `manager.snapshot()` are still
present and already produce display-ready output, so only the transport needs
rewriting.

The last working version also discovered that command templates expand
`` !`shell command` `` via `on.shell()`, substituting stdout before the prompt is
built. That is the only way to get function-generated content into a command
without a tool round-trip, and is worth remembering.

```ts
    config: async (config: {
      command?: Record<
        string,
        { template: string; description?: string; agent?: string; model?: string; subtask?: boolean }
      >;
    }) => {
      config.command ??= {};
      // The template is a placeholder only. `command.execute.before` below
      // replaces it with the rendered dashboard, so the status is produced by
      // code rather than by asking a model to call a tool.
      // opencode expands !`...` in templates by running the shell and
      // substituting stdout, so the dashboard is generated by a function
      // rather than by asking a model to call a tool. A model turn is still
      // unavoidable (the command path always prompts), so the model is pinned
      // to a free model and told to emit nothing.
      config.command[POOL_COMMAND_NAME] ??= {
        description: "Show Claude account pool status (ready / cooling / disabled)",
        template: POOL_COMMAND_TEMPLATE,
        model: POOL_COMMAND_MODEL,
        subtask: false,
      };
    },
```
